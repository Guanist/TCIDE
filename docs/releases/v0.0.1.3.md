# 虎猫 TCIDE v0.0.1.3

这一版的主角是桌面宠物：它从"画在界面里的小图"变成一只真正浮在桌面上、可以拖走的虎猫。顺带把发布与 CI 上的几个坑填了。

## 安装

```bash
# 发布包
pip install tcide-0.0.1.3-py3-none-any.whl
tcide

# 或者从源码
pipx install .
tcide
```

wheel 里已经带了构建好的前端与宠物美术，装完直接能用，不需要联网取资源。

## 桌面宠物

`tcide` 启动时会另外开一个小窗口放宠物：透明背景、没有标题栏、始终置顶。按住窗口任意位置就能拖，放手之后位置会被记住，下次打开还在那儿。

宠物跟着会话走：待机、埋头干活（这时候它会亮出一台小笔电）、打盹、出错四种样子。闲置几分钟它自己会睡，有动静立刻醒。不想看就加 `--no-pet`。

美术是手画的矢量图，导出成透明 PNG 和会呼吸的 GIF 放在 `web/icons/pet/`，每种状态一份。改图改 `web/icons/pet/tcide-pet.svg`，然后跑：

```bash
python tools/render_pet_bitmaps.py
```

它会用无头浏览器把矢量图渲染成位图，再裁边、缩放、合成 GIF。

## 位置是怎么记住的

PyWebView 没有"窗口被移动"事件，所以读不到拖动结果。起点是 `Window.x` 和 `Window.y` 可读，于是把轮询放在 `webview.start()` 的后台槽位里，位置变了就写进 `settings.extra`。

存进去的坐标会用之前会先做一次范围检查。换显示器或者改分辨率之后，旧坐标可能落在屏幕外，那就会变成一只看不见的宠物，这比忘记位置更糟。

## 文档

README 重写了一遍。以前它把项目内部的验证过程写成了正文，安装说明重复三遍，前端资源的来源也写错了（说成运行时要联网取，实际是随包分发），目录结构里还列了一个只剩 `__init__.py` 的模块。现在补上了此前完全缺失的一段：第一次运行怎么配模型。

同时加了一道文档风格检查，`python tools/readme_style.py` 会把加粗密度、正文里的核对符号、自指措辞、成对模板句式这些数出来并设阈值，发布说明也在检查范围内。

## CI 与打包

- `tests` 工作流以前手写安装清单，漏了 `uvicorn`，而 `main.py` 顶层就 import 它。测试一 `import main` 就在收集阶段整体失败，报错还是难以定位的 collection error。现在改成按 `requirements.txt` 安装，只排除 `pywebview`（桌面窗口用，测试用假模块代替）。
- 前端构建产物加了一份提交号记录。同步脚本 `tools/sync_frontend_from_ci.py` 会比对产物提交与本地 HEAD，不一致就拒绝同步 —— 之前手工同步过一次更早提交的产物，把已经删掉的代码又搬回了 `web/`。
- 发布产物校验增加了宠物页面与位图资源的断言。

## 需要你自己确认的一点

宠物窗口的置顶效果和拖动的手感，我在无头环境里验证不了，只能靠测试断言窗口参数（透明、无边框、置顶、可拖动）。实际用起来是否顺手，请实机跑一次看看。

## 验证脚本

```bash
python tools/verify_release.py    # 校验产物内容，并真装进干净 venv 起服务
python tools/verify_install.py    # 源码安装路径
python -m pytest -q               # 全量测试
python tools/readme_style.py      # 发布文档风格检查
```

## 已知问题

- LSP 开箱只有 Python 能用，其他语言需要自行安装对应的服务器，界面会给出安装命令。
- Monaco 的浅色主题是一套手工对齐的独立定义，因为 Monaco 的主题 API 只认具体色值。改主题颜色要同时改两处。
- 冻结打包（PyInstaller 之类）在开发机上不可用：冻结后的 PySide6 在 `QApplication()` 处崩溃，已确认与项目本身无关。安装请走 pip。
- 启动时偶尔会冒出一个上下文菜单，原因未查清。
