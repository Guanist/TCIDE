# 虎猫 TCIDE v0.0.1.2

这个版本把项目从"克隆仓库、手动装依赖、`python main.py`"变成 `pip` / `pipx` 可装可跑，同时修掉了语言服务器和 MCP 两处"看起来能用、实际一次也没通"的问题，前端也终于有了可维护的主题源码。

本页的 wheel 由 tag 指向的那次提交构建。`main` 上还有 tag 之后的改动（桌面宠物等），想要最新的就从源码装。

## 安装

```bash
# 发布包
pip install tcide-0.0.1.2-py3-none-any.whl
tcide --browser

# 或者从源码
pipx install .
tcide
tcide --no-window        # 只要后端服务
tcide /path/to/project   # 指定项目目录
```

## 改动

### 安装

补上了 `pyproject.toml`（含 `tcide` 命令入口）和 `MANIFEST.in`。此前仓库没有任何安装元数据。

顺带补了 `api/`、`adapters/`、`agents/`、`web/`、`static/`、`pet_assets/` 六个目录的 `__init__.py`。缺这些文件 setuptools 会把整个目录漏掉，装完直接 ImportError。

### 语言服务器

探测阶段把裸命令名存进了 `status.command`。Windows 的 CreateProcess 不解析 npm 生成的 `.CMD` shim，结果界面显示"可用"，客户端却永远连不上。现在存的是 `shutil.which()` 解析出的绝对路径。

### MCP

原来的帧协议照抄了 LSP 的 Content-Length 写法，而 MCP stdio 是一行一个 JSON，于是一条响应都解析不到。改成按行读，后台线程负责收，按请求 id 派发。

外部工具现在会注册进工具表，模型可以直接调用。

同时修了一个权限漏洞：策略按工具名判断，认不出 `fs__write_file` 这类外部工具的名字，只读档下会把它们放行。现在改为按 `ToolSpec.dangerous` 判断，外部工具一律标危险。

### 编排

- best-of-N：同一需求在隔离副本里各跑一遍，按完成率、测试结果和改动规模打分挑一份，胜出的经审核门回收而不是直接写盘。
- 长任务检查点：写在实际任务边界。恢复时会把"结果未知"的工具单独列出来，要求先核验副作用再决定重试，避免盲目重跑已经落盘的写操作。
- 任务级并行原本就有（`ThreadPoolExecutor` + `max_parallel_coders`），这版没有重复实现，只是把口径写清楚了。

### 主题与前端

前端源码此前不在仓库里，只有构建产物。这版从归档分支取回了 `src/renderer/`、`src/core/`、`vite.config.ts` 和 `package.json`。

浅色主题做进了源码：`main.css` 里 24 处绕过变量直接写死的色值收敛回 `var()`，并删掉了与之并存的另一套 `.theme-light` 变量块。新增 `static/tcide-theme.{css,js}` 作为覆盖层与切换入口，支持 `?theme=light|dark`。

CI 加了 `frontend` 工作流，在干净 runner 上重建前端并校验主题确实进了产物。

### 同版本内的后续修复

Monaco 的浅色主题之前不生效。问题出在判断上，而不是主题定义缺失：创建编辑器时只看 `localStorage`，而 `?theme=light` 有意不写它；更麻烦的是那个显式 `theme` 选项会覆盖全局 `setTheme`。现在统一由 `isLightThemeActive()` 判断（localStorage、类名、data 属性三者取并集）。

界面里的版本串统一到 `v0.0.1.2`。`package.json` 的 `version` 保持合法的三段 semver，对外显示的是 `versionName`。

## 验证脚本

```bash
python tools/verify_install.py    # 干净 venv 里装一遍并起服务
python tools/verify_lsp.py        # 接真 pyright 拿诊断（需要 pyright）
python tools/verify_mcp.py        # 接真 MCP server 并调用工具（需要一个 MCP server）
python tools/verify_release.py    # 校验发布产物内容并真装一遍
python -m pytest -q               # 全量测试
python tools/api_audit.py         # 前后端接口对账
```

## 已知问题

- 本地构建前端不可用：开发机仓库外两层的 `package.json` 是坏的（一份被截断的 React Native 清单），esbuild 解析模块类型时会读到它并失败。前端构建因此走 CI。
- LSP 开箱只有 Python 能用，其他语言需要自行安装对应的服务器。
- 启动时偶尔会冒出一个上下文菜单，原因未查清。
