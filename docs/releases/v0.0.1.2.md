# 虎猫 TCIDE v0.0.1.2

这一版把 TCIDE 从「克隆仓库 + 手动装依赖 + `python main.py`」推进到 **`pip` / `pipx`
可装可跑**，并把语言服务器、MCP、编排深度、前端主题这几块补上真实可验证的能力。

## 安装

```bash
# 方式一：从本页下载 wheel（前端资源已随包分发，装完就能开界面）
pip install tcide-0.0.1.2-py3-none-any.whl
tcide --browser

# 方式二：从源码装
pip install .          # 或 pipx install .
tcide                  # 原生窗口（PyWebView）
tcide --no-window      # 只跑后端服务
tcide /path/to/project # 指定项目目录
```

## 本版主要变化

**① 能装上了**
- 新增 `pyproject.toml`（含 `tcide` 命令入口）与 `MANIFEST.in`；此前项目**没有任何安装元数据**。
- 补 6 个目录的 `__init__.py`（`api/`、`adapters/`、`agents/`、`web/`、`static/`、`pet_assets/`）
  —— 缺这些会被 setuptools **静默漏装**，装完必然 `ImportError`。
- `tools/verify_install.py`：在干净 venv 里真装真跑，并自证"跑的是安装后的那份"。

**② 真实语言服务器**
- 修一个致命缺陷：探测阶段把**裸命令名**存进了 `status.command`，而 Windows 的
  `CreateProcess` 不解析 npm 的 `.CMD` shim —— 界面显示"可用"，实际**永远连不上**。
  现在存 `shutil.which()` 解析出的绝对路径。
- `tools/verify_lsp.py`：接真 pyright，断言能拿到真诊断。

**③ MCP 客户端**
- 修帧协议：原实现按 LSP 的 `Content-Length` 收发，而 **MCP stdio 是一行一个 JSON**，
  于是永远解析不到响应。改为按行读 + 按 id 派发 + 后台读线程。
- 外部工具现在**接进工具表**，AI 能真正调用（此前是"能力在、接线没接"）。
- 修一个真实安全洞：权限策略按工具名判断，认不出 `fs__write_file` 这类外部工具，
  **只读档下会放行**。现在由 `ToolSpec.dangerous` 驱动，外部工具一律标危险。

**④ 编排深度**
- **best-of-N**：同一需求在**隔离副本**里跑多个尝试，按明确口径选优
  （完成率为主项、测试通过为最强加分、改动规模轻微扣分），胜出者**经审核门**回收。
- **长任务恢复**：语义检查点写在实际任务边界；恢复判定会标出"结果未知的工具"
  并要求先核验副作用（盲目重跑比中断更危险）。
- 说明：任务级并行**本来就有**（`ThreadPoolExecutor` + `max_parallel_coders`），
  本版没有重复实现它，只把它标注清楚。

**⑤ 前端主题**
- 前端源码此前**不在仓库里**（只有 Vite 构建产物）。本版从归档分支恢复了
  `src/renderer/`、`src/core/`、`vite.config.ts`、`package.json`。
- 主题做进**源码**：`main.css` 增加浅色主题（同时响应 `data-tcide-theme` 与
  应用自带的 `.theme-light` 类），把 24 处绕过变量的裸色值收敛为 `var()`，
  并删掉与之并存的**重复** `.theme-light` 变量块。
- 新增 `static/tcide-theme.{css,js}` 皮肤层与主题切换（支持 `?theme=light|dark`）。
- CI 新增 `frontend` 工作流：在干净 runner 上重建前端，并校验主题真的进了产物。

## 验证方式（都可离线重放）

```bash
python tools/verify_install.py    # 装得上、装完能跑
python tools/verify_lsp.py        # 真语言服务器能拿真诊断（需 pyright）
python tools/verify_mcp.py        # 真 MCP server 能握手、能调用（需一个 MCP server）
python tools/verify_release.py    # 发布产物内容完整 + 真装进干净 venv 起服务
python -m pytest -q               # 全量测试
python tools/api_audit.py         # 前后端接口对账
```

已知本机实测结果：安装路径 `in_venv: True`（确实从 site-packages 运行）、
pyright 报出真实类型错误、`fs__list_directory` 经工具注册表返回真实目录内容。

## 已知限制（如实标注）

- **本机无法构建前端**：仓库外两层存在一个损坏的 `package.json`
  （`Desktop/Vincent/package.json`，截断的 React Native 清单），esbuild 解析模块类型时
  会读到它并失败。因此前端构建走 **CI**（`.github/workflows/frontend.yml`，已绿）。
- **浅色主题下编辑器仍是深色**：Monaco 主题色写在 `main.ts` 的 JS 对象里，
  其 API 不接受 CSS 变量。
- **LSP 目前只通了 Python**：其余语言需要自行安装对应服务器，界面会给安装命令。
- 界面里显示的 `v0.0.1` 是前端源码自带的版本串，与发布包版本 `0.0.1.2` 尚未统一。
