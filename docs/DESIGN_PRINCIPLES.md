# 界面设计原则（向 DSH 学"为什么"，不是学"长什么样"）

这份文档记录的是一次**对照学习**：以 DeepSeek Harness（DSH）v0.2.0-rc.2 的真实界面
为参照，提炼它布局背后的**取舍与理由**，再决定 TCIDE 该怎么落地。

写下来的理由很直接：只对着截图改，会变成"照着别人的样子描" —— 形状像了，**为什么**
没学到，换个场景就崩。而且 TCIDE 与 DSH 是**不同的产品**，硬抄会把 TCIDE 自己的优势
（真正的编辑器、离线优先、可审计的写操作）也一起改没。

> 一句话概括两者的定位差异：
> **DSH 是"以智能体为主角的工作台"**，**TCIDE 是"带智能体的 IDE"**。
> 所以下面每条原则的落地方式**允许与 DSH 不同**，但**理由必须成立**。

---

## 从 DSH 界面读到的六条

### 1. 主列是"正在进行的工作"，不是欢迎页

**DSH 的做法**：一屏之内，中央那一列从第一秒起就是**任务流**（消息、工具调用、
耗时、状态行）。没有插画、没有 hero、没有"开始使用"这类落地页元素。

**为什么**：用户打开它是为了**继续干活**。落地页只在第一次有意义，之后每次打开都在
浪费整个视口。

**TCIDE 的落地**（可以不同）：保留欢迎页，但把它从"整页 hero"降级为**主列里的一段
可折叠内容** —— 一旦有会话/文件，它就退场。

**判定标准**：打开应用后，**不需要滚动、不需要点击**就能看到"上次在做什么"。

### 2. 结果就地呈现，不散落到别的面板

**DSH 的做法**：命令输出、文件改动、网页结果都**内联在任务流里**（可折叠、带耗时），
右侧的浏览器面板是**同屏并列**而不是"另开窗口"。

**为什么**：一次操作的"输入 → 执行 → 结果"在空间上连续，人才不用来回找。

**TCIDE 的落地**：工具调用与命令输出已经在源码里有事件流（`AgentEvent`），
把它们渲染成**主列里的可折叠行**，而不是只在"输出面板/问题面板"里。

**判定标准**：看完一次工具执行，**视线不需要离开主列**。

### 3. 状态是环境，不是弹窗

**DSH 的做法**：模型、权限档（"完全权限"）、子智能体数量、耗时、token 速率、
缓存命中率，全部是**常驻的 chip 与一条密集状态行**，随时可见、点击即改。

**为什么**：这些都是**影响信任与判断**的信息（谁在干活、有多大权限、花了多少）。
藏进设置弹窗，用户就只能靠猜。

**TCIDE 的落地**：把"模型 / 权限档 / 子代理数 / tokens"做成常驻 chip；
状态栏补上耗时与轮次。数据都已有（`/api/usage`、权限三档、编排统计），只是没显示。

**判定标准**：任何时刻都能一眼回答"**谁在干、有多大权限、花了多少**"，且不用打开对话框。

### 4. 渐进披露：默认安静，需要时展开

**DSH 的做法**：工具调用行默认折叠、只显示一行摘要与耗时；会话列表显示相对时间
（"1分钟""11天"）；左缘图标轨只在悬停时出现名称。

**为什么**：细节多的界面不是"信息丰富"，是"噪音大"。**默认值**决定了界面的安静程度。

**TCIDE 的落地**：优先级的判断 —— **不是所有名称都该藏起来**。
活动栏的中文标签对中文用户是**发现性**（discoverability）资产，保留；
该折叠的是**内容级**细节（工具输出、长 diff、日志）。

**判定标准**：默认视图里，**每个像素都在回答用户当下的问题**。

### 5. 强调色克制：主动作只有一个颜色，语义色只给内容

**DSH 的做法**：界面的主动作是一个冷色（发送键、选中态）；橙色/绿色这类颜色
**只出现在内容里**（勾选、标记、代码高亮）。所以主次一眼分明。

**为什么**：强调色用满，等于没有强调。

**TCIDE 的落地**：橙色是虎猫的**身份色**（保留，这是品牌而不是噪音），但
**主动作与选中态**要与"内容里的橙"分开层级 —— 例如主动作用实心橙、状态用描边橙。

**判定标准**：截图上把颜色去掉，**主次关系依然成立**。

### 6. 非阻塞并列：面板共存，而不是模式切换

**DSH 的做法**：会话 / 任务流 / 浏览器三栏**同时存在**，宽度可调，各自有安静的头部。

**为什么**：智能体在**后台跑**的时候，人应该能同时读文档、看 diff —— 而不是被
模态挡住或被迫切模式。

**TCIDE 的落地**：编辑器、AI 轨迹、预览**并列可调**；把"浏览器测试"从独立窗口
改成主区里的一个可停靠视图（`web/` 里已有该页面）。

**判定标准**：智能体在跑的过程中，**用户仍能自由操作界面**，且不需关闭任何模态。

## 明确"不照抄"的清单

学原则不等于抹掉自己。以下**刻意保持与 DSH 不同**：

| 项 | 为什么保留 |
|---|---|
| 活动栏的中文文字标签 | 中文用户的发现性；藏起来只是在模仿"图标轨"的形状 |
| 橙色作为身份色 | 虎猫的识别色；DSH 用冷色主动作是它的选择，不是普适规则 |
| 编辑器为主区 | TCIDE 是 IDE —— 编辑器是主区，AI 是协作者；DSH 是反过来的 |
| 离线优先 / 无网可用 | 产品定位差异，与布局无关但同属"不抄" |
| 写操作可审 | 权限与变更提案是 TCIDE 的信任基础，不为了"顺滑"而削弱 |

## 怎么验证"学到了"而不是"抄到了"

1. **不看截图问自己**：这条改动是让"用户在回答自己的问题"更顺，还是只是更像别人？
   答不出前者就不做。
2. **可测量的代理指标**：首屏信息密度（首屏可见的可操作项数量）、
   完成任务所需的面板切换次数、模态弹窗数量（应当趋近 0）。
3. **回归测试**：结构性的东西（状态 chip 常驻、工具行可折叠、面板可调宽）
   都要有离线测试钉住，避免下次改样式时又丢回去。
